# slides

スライドは Claude の Slides Artifact で作る（Marp は使わない）。この手順は 2026-11 の
WebMCP 勉強会の資料（`2026/webmcp/`）で確かめた作り方をそのまま決まりにしたもの。
雛形は `templates/`、機械で見られる決まりは `scripts/check-deck.py` が見る。

## 0. 最初に確かめること（質問は 1 つにまとめる）

発表の日付、場（社内・外部・公開予定）、聴衆の層（初級〜上級）、持ち時間、
伝えたいこと 2 つまで。足りないものだけを 1 回で聞く。聞かずに推測で埋めない。

枚数の目安: 持ち時間 1 分あたり 1 枚。章の区切りと表紙・目次・出典を含めて数える。

## 1. 構成

1. 表紙（題は結論。日付・名前は入れない）
2. 目次（章は 5 つまで。「話さないこと」を 1 行添える）
3. 各章の前に区切りの枚（目次を再掲し、今の章だけ大きく）
4. 本文。1 枚 1 主張。「理由 1〜3」のように番号で束ねるときは、同じ番号の枚すべてに
   `eyebrow` を付ける
5. おわり（持ち帰る 1 文。前の枚の繰り返しにしない）
6. 出典（最後の 1 枚にまとめる。本文の各枚には散らさない）

言葉の説明が続く前半には、公式の動画や図を 1 枚入れて「動き」を先に見せる。

## 2. デザインの決まり

大木尊紀氏「『見せる』登壇資料デザインの極意」（<https://youtu.be/rIueuWNfcCQ>）に従う。

- 題で結論を言う。「〜について」「〜の紹介」にしない
- 箇条書き（ul/li）とカード（枠で囲った小さな箱）を使わない。列挙は `.line` の行に番号の目印
- 1 枚 5 行まで。入らなければ枚を分ける。文字を小さくして詰めない
- 文の途中で折り返さない。長い行は意味の切れ目に `<br>` を入れる
- 白地、2 色（紺 `--base` と橙 `--accent`）、補助の灰 `--sub`。すべて白地で 9:1 以上
- 左揃え。本文は題の下 88px から始める（`.mid`。縦中央に置かない）
- 本文 48px（長い行は 44px）。表 40px、流れ図 36px、時系列 30px、出典 28px が下限
- 動きの演出を入れない（`data-transition="fade"` だけ）
- 図は読み取ることを題に書く。alt に中身を文で書く
- 聞き手が「どれに対応しているか」を探さない配置にする（番号と結果は同じ行、表は列をそろえる）

## 3. 作り方（Artifact）

1. `Artifact` の `quickstart` を `intent: "slides"` で呼び、Slides の type から新しい Artifact を作る
2. 作業フォルダ（scratchpad）に `project/deck.json`、`project/deck.css`、`project/slides/<id>.html` を置く。
   出発点は `templates/deck.json`、`templates/deck.css`、`templates/slides/*.html`。
   deck.css は変えずに使い、足りない部品だけ末尾に足す
3. 1 枚 1 ファイル。`<section id="…">` が本文、末尾の `<aside>` が話す原稿。`id` は英小文字
4. 画像・GIF は `asset: true` で上げ、`/_blob/<id>` で参照する。YouTube は iframe で埋め込む
   （表示では「再生ボタン＋Open on YouTube」の枠になり、押すと新しいタブで開く。枠の中では
   再生されない。`a` タグのリンクはプレゼン表示で効かない）
5. 公開は `url` + `root`（作業フォルダ）+ `file_path`（deck.json）+ `files`（変えた枚）
6. **公開の前に必ず `action: "read"` で相手の最新版を読む。** オーナーがページ側で直接
   直していることがあり、古い手元の写しで公開すると上書きになる（衝突は拒否される）

## 4. 文面

- 日本語の本文と話す原稿は、書いたら必ず `yomiyasu` を通す
  （`run --stdin --doc-type slides --stance=説明 --fact-gaps` → 直すのは 1 回 → `verify --final -`）。
  確認の記録を返答に付ける
- 推測で事実を足さない。数値・固有名詞・日付は出典の枚で裏が取れるものだけ
- 固有名詞には何の名前かを添える（「Chrome の Gemini、Edge の Copilot、拡張機能の Claude in Chrome」）。
  製品名が文に見えると読み違える
- 不自然と言われた言い回しを避ける: 「呼ぶ側／提供する側」→「AI 側／サイト側」、
  「作業部会」→「標準化に向けて合意」、「編集者」→「仕様を書いているのは」、
  「入口」→「書き方」、「道具になる」→「使えるようになる」、「構想を読む」「知っておく」は使わない
- 課題や否定の材料は「理由」の枚に混ぜず、課題の枚にまとめる
- 「今後」の枚は前の章の繰り返しにしない。この先に起きることだけを書く

## 5. 確かめ方（公開のたびに）

1. `python3 scripts/check-deck.py <作業フォルダ>/project` を実行し、エラー 0 にする
2. Chrome で Artifact を開き、変えた枚を 1 枚ずつスクリーンショットで見る。
   見るのは、折り返し（語の途中で切れていないか）、はみ出し、題の行数、本文の開始位置
3. プレゼン表示（▷ → Present）でも 1 度通す。リンクや動画の枠はここでしか確かめられない
4. 全体を通しで読み、同じ区別を 3 枚で繰り返していないか、章の中で見た目がそろっているかを見る
5. 出典の枚に、本文に出る数値・固有名詞の出所が全部あるかを見る

オーナーが「気になるところはない」と言うまで 1 枚ずつ直す。直すたびに 1〜3 を繰り返す。

## 6. リポジトリへの置き方

`<year>/<kebab-topic>/` に次の 2 つを置く。ソース（deck.json・deck.css・slides）は Artifact 側に
あるので置かない。

- `README.md`: 題、日付、場、Artifact の URL、デモや動画の URL、書き出しの注意
- `slides.html`: Artifact のページの ⬇ → Web page (.html) で書き出した単体の HTML
  （ダウンロードはオーナーの操作。`~/Downloads/<題>.html` を写す）。
  動画の埋め込みは黒い枠になるので、URL の文字を枚に残しておく

コミットは main に直接でよい。push は頼まれてから。
