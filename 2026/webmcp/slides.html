WebMCP とは
開いている Web ページの機能を AI から直接呼び出せるようにするブラウザの API
開発者は、ページの関数をツールとしてブラウザに登録する
AI は、入力欄やボタンを探す代わりにその関数を呼ぶ
人は従来どおりフォームを使う。結果は人と AI の両方に出る
Google と Microsoft が W3C（Web の標準化団体）のコミュニティグループに出している草案。 正式な標準になる前の段階なので、API の名前や動きは今後変わることがある
4
利用者はいつものページで AI に頼むだけ
1 ホテルの検索ページを開いている（ログイン済み）
2 AI に「駅から徒歩 10 分以内に絞って」と頼む
3 ページの絞り込み機能が動き、一覧がその場で絞られる
AI はページが登録した「絞り込み」のツールを呼ぶだけ。サイトに新しいサーバーは要らない

7
登録は 4 項目。execute は検索ボタンと同じ関数を呼ぶ
await document.modelContext.registerTool({
name: "search_products",
description: "予算の上限以下の商品を検索し、画面に表示します。",
inputSchema: {
type: "object",
properties: { maxPrice: { type: "integer", minimum: 0 } },
required: ["maxPrice"],
},
execute: async input => searchProducts(input),
});
8
4 項目のうち、要は execute に既存の関数を渡すこと
name
ツール名。AI はこの名前でツールを呼ぶ
description
AI がツールを選ぶ手がかり。何をするかを日本語で書く
inputSchema
受け取る値の条件（JSON Schema）
execute
実行する関数。検索ボタンと同じ関数を呼ぶ

フォームに属性を足すだけでも、ツールになる
<form toolname="search_products" tooldescription="予算の上限以下の商品を検索する">
<input name="maxPrice" type="number" toolparamdescription="予算の上限。日本円">
<button>検索</button>
</form>
宣言的 API: 既存のフォームに toolname と tooldescription を足す
入力欄の説明は toolparamdescription に書く

3 つとも AI に機能を使わせる仕組み。 違いは、機能がどこにあるか
MCP
AI アプリ（Claude、ChatGPT など）が外部サービスの機能を使う共通の決まり。 機能は MCP サーバーというプログラムが提供し、AI アプリがそれを呼ぶ
MCP Apps
MCP の拡張。ツールの結果を HTML の画面にして、チャットの中に埋め込む
WebMCP
開いている Web ページの機能を、ブラウザを通して AI に使わせる

20
普及の条件は 3 つそろいつつある
1 作る側のコストが低い: 既存の関数やフォームを登録するだけ
2 標準化の後ろ盾がある: Google と Microsoft が提案し、W3C でも標準化に向けて合意
3 対応する AI とサイトが増えている: ChatGPT、Brave、Shopify
21
理由 1
作る側のコストが低い
既存の関数かフォームを登録するだけ。AI 向けの別の API は要らない
利用者がログインした状態をそのまま使える。認証の仕組みを別に作らない
AI 向けのサーバーを動かし続けなくてよい。ページを開いている間だけ動く
22
理由 2
標準化の後ろ盾がある
仕様を書いているのは Google と Microsoft。2 社の共同提案
Chrome 149 から、Edge 150 から試験提供（Origin Trial）
W3C でも標準化に向けて広い合意（2026 年 10 月）
23
理由 3
ブラウザ側は Chrome と Edge が試験提供中、 Brave は標準で有効へ
Chrome: 149 から Origin Trial（試験提供）。162 まで延長
Edge: 150 から Origin Trial。9 月に「Edge で試せる」と発表
Brave: 11 月、内蔵の AI チャット（Leo）で標準で有効にする変更が入った
24
理由 3
AI 側は ChatGPT が先行、 MCP Apps も WebMCP と同じ API へ
ChatGPT: 8 月、デスクトップの内蔵ブラウザが WebMCP のツールに対応
MCP Apps: 11 月の更新で、WebMCP と同じ登録 API に対応
Shopify: 全ストアで、商品検索などの WebMCP ツール 17 個を提供
Google I/O で実験中と紹介: Expedia、Booking.com、Etsy、Instacart、Target など
25
理由 3
2026 年は 2 月の先行提供から毎月動きがある
2 月
Chrome が 先行プログラムで 提供開始 （Early Preview）
5〜6 月
Google I/O で発表 Chrome 149 で 試験提供を開始 （Origin Trial）
6〜8 月
Safari 側は反対 Firefox 側は中立 ChatGPT が対応
9〜10 月
Edge で試せる W3C でも 標準化に向けて 広い合意
11 月
MCP Apps が 同じ API に対応 Brave が標準で有効化 仕様の草案を更新

27
広がるには、残る課題が 3 つ
1 Safari は反対、Firefox は中立。全ブラウザがそろう見通しはない
2 仕様は草案で、API が変わる。5 月には書き方が navigator から document に変わった
3 主要な AI は未対応: Chrome の Gemini、Edge の Copilot、 拡張機能の Claude in Chrome
28
採用前に確かめることは 5 つ
1 仕様は草案。API は変わりうるので、実装状況のページで確認する
2 本番で使うなら Origin Trial（試験提供への申し込み）に登録する
3 ツールはページを開いている間だけ。AI は開くまでツールを知らない
4 取り消せない操作は、実行前に利用者が画面で確認する流れにする
5 inputSchema の条件はブラウザが強制するとは限らない。関数でも確かめる
29
この先の節目は 3 つ。 正式提供、W3C の標準化、残りの AI の対応
1 Origin Trial は Chrome 162 まで。正式提供の発表はまだない
2 W3C で標準化の作業が進む。仕様は草案のまま更新が続く
3 未対応の Gemini（Chrome）、Copilot（Edge）、 Claude in Chrome（拡張機能）が対応するかどうか
30
おわり
WebMCP は今日から 手元で試せる段階まで来ている
WebMCP はブラウザの API。MCP を置き換えるのではなく補う
自社サイトを開いている間の操作は WebMCP、ページを開かずに使う処理は MCP
今日のサンプルと手順は Qiita の記事にある
